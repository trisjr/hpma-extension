# Tự động hóa quản trị Business Manager (Admin & Assets)

> Phạm vi: các tác vụ quản trị BM hay phải làm thủ công — người dùng & phân quyền, gán/gỡ assets (Page, Ad Account, Pixel/Dataset, Catalog, IG, WABA), share assets giữa các BM (agency flow), System Users + token, quản lý nhiều BM/ad account, business verification, spending limits. Trạng thái nghiên cứu: **tháng 10/2026**.

---

## 1. Tổng quan

**Bối cảnh phiên bản (xác minh 10/2026):**

- Graph API mới nhất là **v26.0** (Meta Business SDK v26.0.0 phát hành 06/08/2026, bản vá mới nhất 26.0.2 ngày 21/09/2026 — xác minh qua GitHub Releases của `facebook/facebook-php-business-sdk` và `facebook/facebook-nodejs-business-sdk`, và qua probing `graph.facebook.com/v26.0/`).
- Release cadence hiện ~3–4 tháng/1 version (v22: 02/2025, v23: 06/2025, v24: 10/2025, v25: ~03–04/2026, v26: 08/2026).
- Chính sách vòng đời: mỗi version được hỗ trợ **~2 năm**. Timeline sunset đã công bố trong release notes v26: Platform SDK v20.0 sunset 09/2026, v21.0 sunset 01/2027 → khi build extension nên pin `v26` nhưng code theo cách dễ bump version.
- Lưu ý UI: từ 2023–2024 Meta đổi tên Business Manager thành **Meta Business Portfolio** trong UI (`business.facebook.com`), nhưng tên API vẫn là **Business** object / Business Management API.

**Bức tranh chung:** Meta cung cấp Business Management API (một phần của Marketing API/Graph API) khá đầy đủ cho **đọc/cấu hình hàng loạt**: người dùng (invite/remove), system users + token, gán/gỡ assets cho people/partner BM, request/claim assets, agencies (BM-to-BM), theo dõi trạng thái ad account (bị hạn mức/vô hiệu hóa) và verification status. Các bước **có yếu tố con người ở phía bên kia** (approve lời mời, nộp giấy tờ verification, chấp nhận invite link, xác nhận chuyển quyền sở hữu) **không thể hoàn toàn tự động** — chỉ làm được "hybrid" (API gửi yêu cầu + UI/đối tác duyệt) hoặc "UI-only" (browser automation trong Business Settings).

## 3. Chi tiết kỹ thuật

### 3.1. Auth & permissions

| Mục đích                                                   | Permission/Access                                                                                              | Ghi chú                                                                                                  |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Quản lý BM: invite/remove people, system users, gán assets | **`business_management`**                                                                                      | Cần **App Review → Advanced Access**; Standard Access chỉ cho dữ liệu BM sở hữu bởi chính người dùng app |
| Gán/quản trị Ad Account                                    | `ads_management` (+ `ads_read` cho đọc)                                                                        | Spending, account status                                                                                 |
| Gán/quản lý Page                                           | `pages_read_engagement`, `pages_manage_ads`, `pages_show_list` (đọc danh sách), thêm `public_profile` mặc định | New Page Experience: tasks dạng `PROFILE_PLUS_*`                                                         |
| Đọc insights/billing                                       | `ads_read`                                                                                                     | —                                                                                                        |
| System user token                                          | Token hệ thống (máy ↔ máy)                                                                                    | Không áp dụng OAuth user flow; tạo theo §3.3                                                             |

**Cơ chế xác thực cho extension:**

1. OAuth Login flow (extension dùng `chrome.identity.launchWebAuthFlow`): scope `business_management, ads_management, pages_read_engagement, pages_show_list, ads_read`. User token ngắn hạn (~1h) → đổi long-lived (~60 ngày) qua `GET /oauth/access_token?grant_type=fb_exchange_token`.
2. System User token dán tay: người dùng tạo trong Business Settings → paste vào extension. Phù hợp cho automation nội bộ (agency). Token dài hạn, ít rủi ro phiên bị kill; mất token = mất quyền → phải lưu trong `chrome.storage` có cảnh báo, hoặc mã hoá.
3. Lưu ý: token không expire chỉ đúng với "never expires" ticked; admin có thể revoke toàn bộ tại System Users UI.

### 3.2. Các endpoint quan trọng (Graph API v26, object `Business`)

**People & requests:**

- `GET/POST /{business_id}/business_users` — danh sách & invite (param `email`, `role` = `ADMIN`/`EMPLOYEE`/`FINANCE_EDITOR`/`FINANCE_ANALYST`)
- `DELETE /{business_id}/business_users/{business_scoped_user_id}` — remove
- `POST /{business_id}/business_users/{bsuid}` — cập nhật role/finance role, gán business (param `business` khi thêm người vào BM từ BM khác)
- `GET /{business_id}/pending_users` — lời mời đang chờ
- `GET /{business_id}/clients`, `GET /{business_id}/agencies`; `DELETE` tương ứng
- `GET /{business_id}/business_users/{id}/assigned_pages|assigned_ad_accounts|assigned_product_catalogs|assigned_business_asset_groups|assigned_whatsapp_business_accounts`

**System users & token:**

- `GET/POST /{business_id}/system_users` (`name`, `role`)
- `POST /{business_id}/system_user_access_tokens` (`system_user_id`, `business_app` = app ID, `scope` = danh sách permission CSV) → trả về access token
- Phía UI: Business Settings → Users → System Users → chức năng "Add", "Generate token", "Revoke tokens" (xem `Admin panel`)
- System user xem assets: `GET /{system_user_id}/assigned_pages|assigned_ad_accounts|...`

**Assets inventory:**

- Pages: `GET /{business_id}/owned_pages`, `GET /{business_id}/client_pages`, `POST client_pages` (request), `POST owned_pages` (claim), `DELETE /{business_id}/pages`
- Ad accounts: `GET owned_ad_accounts` / `client_ad_accounts`; `POST /{business_id}/adaccount` (request access); `POST owned_ad_accounts` (claim); `DELETE /{business_id}/ad_accounts`
- Pending: `GET /{business_id}/pending_client_pages`, `pending_owned_pages`, `pending_client_ad_accounts`, `pending_owned_ad_accounts`, `pending_client_apps`, `pending_shared_offsite_signal_container_business_objects`
- Pixels/datasets: `GET owned_pixels`, `client_pixels`, `POST /{business_id}/adspixels` (tạo pixel), `POST /{business_id}/pixel_tos` (chấp nhận ToS pixel), `GET/POST /{business_id}/ads_dataset`
- Catalogs: `GET owned_product_catalogs`, `client_product_catalogs`, `POST owned_product_catalogs`
- Apps: `GET/POST owned_apps`, `GET/POST client_apps`, pending_client_apps
- Instagram: `GET instagram_accounts`, `owned_instagram_accounts`, `client_instagram_assets`, `DELETE instagram_accounts`
- WABA: `GET owned_whatsapp_business_accounts`, `client_whatsapp_business_accounts`
- Báo cáo: `GET /{business_id}/ad_account_infos` (`account_id`, `account_status`, `amount_spent`, `balance`...)
- Logs: Business Setting Logs (object `BusinessSettingLogsData`: `actor`, `event_object`, `event_type`, `event_time`, `extra_data`)

**Gán/gỡ quyền trên từng asset:**

- `GET/POST/DELETE /{asset_id}/assigned_users` với `{user: <BSUID hoặc FBUID>, business: <business_id>, tasks: [...]}` — Page, Ad Account, Pixel, Catalog, App (roles), WABA
- Agency: `GET/POST/DELETE /{asset_id}/agencies` `{business: partner_bm_id, permitted_tasks: [...]}`
- Pixel share: `/shared_accounts`, `/shared_agencies`

**Ad account status/spending:**

- Fields: `account_status`, `disable_reason`, `spend_cap`, `min_campaign_group_spend_cap`, `amount_spent`, `balance`, `is_prepay_account`, `funding_source`, `funding_source_details`, `expired_funding_source_details`, `min_daily_budget`, `currency`, `timezone_id`, `owner`, `owner_business`, `business`, `user_access_expire_time`, `is_tax_id_required`, `tax_id_status`
- `account_status` codes: **1 ACTIVE, 2 DISABLED, 3 UNSETTLED, 7 PENDING_RISK_REVIEW, 8 PENDING_SETTLEMENT, 9 IN_GRACE_PERIOD, 100 PENDING_CLOSURE, 101 CLOSED, 201 ANY_ACTIVE, 202 ANY_CLOSED**

### 3.3. System User token — lưu ý ứng dụng

- Tạo nhanh qua UI (Business Settings → Users → System Users → Generate new token): chọn app + permissions; có checkbox "token never expires" tuỳ cấu hình hiện hành.
- Qua API: `POST /{business_id}/system_user_access_tokens` — cần caller là admin BM + `business_management`; app phải đã grant các permission trong `scope`.
- Lần đầu tạo/access yêu cầu: **admin bật 2FA**, BM **đã business-verified** (prereq Meta công bố từ 2023 — kiểm tra lại khi implement vì hay thay đổi).
- System user phải được **gán asset** (assigned_users) + **gán vào app**; tokens không thay đổi khi system user đổi tên; revoke nhanh bằng System Users UI → "Revoke".

### 3.4. Rate limits & lỗi thường gặp

- **Business Use Case rate limit** (Marketing API): theo header `x-business-use-case-usage` (phần trăm `call_count`, `total_time`, `estimated_time_to_regain_access`) — đạt 100% sẽ chặn (error code dạng 80004).
- **App-level/User-level rate limit** (Graph API chuẩn): headers `x-app-usage` / `x-ad-account-usage`; lỗi điển hình: code **4** (Application request limit), **17** (User request limit), **613** (Calls to this API have exceeded the rate limit — gắn ad account), **32** (page-level throttle).
- **Batch API:** `POST https://graph.facebook.com/` body `batch=[...]` tới **50 sub-requests/batch** — bắt buộc dùng khi gán quyền hàng loạt để giảm số HTTP call (nhưng sub-call vẫn tính vào rate limit).
- Chiến lược: đọc audit list trước (assigned\_\* edges), grouping theo asset, exponential backoff, hàng đợi 1 rps cho operations ghi khi quét số lượng lớn BM.
- Invite email hàng loạt có **giới hạn pending invites per BM**; Meta chống spam rất mạnh (giới hạn ~hàng trăm/ngày tùy BM — không công bố cố định, cần kiểm ứng thực tế).
- Mỗi BM có limits về số ad account sở hữu/tạo mới (tăng dần theo lịch sử chi tiêu — "ad account creation limit"); đọc hiển thị tại Business Settings → Business info (UI); API không có field công khai ổn định cho con số này.

### 3.5. Browser extension (MV3) — lưu ý triển khai

- Gọi Graph API trực tiếp từ **background service worker** (`fetch` tới `https://graph.facebook.com/v26.0/...`). Graph API hỗ trợ CORS cho request mang access token → không cần proxy server. Declared host permissions: `https://*.facebook.com/`, `https://graph.facebook.com/`.
- `chrome.identity.getAuthToken` **không** dùng được cho Meta OAuth (Meta không nằm trong OAuth2 built-in của Chrome); dùng `chrome.identity.launchWebAuthFlow` với redirect `https://<ext-id>.chromiumapp.org/`, hoặc nhận token từ máy chủ trung gian của mình.
- Với tác vụ UI-only (verification upload, xem "Business info", accept invite): tự động hoá cẩn trọng qua **content script** trên `business.facebook.com`; Meta chạy anti-automation (request signing, checkpoint); rủi ro cao nếu automation spam → tài khoản user bị đánh dấu. Chỉ nên "semi-automated" (điền sẵn form, hỏi người dùng trước khi click submit).
- Cookie session của `business.facebook.com` có thể dùng cho một số internal GraphQL nhưng **vi phạm ToS** và không ổn định (CSRF token rotation) — **không khuyến nghị**.
- Lưu token: `chrome.storage.session`/`storage.local` + (nếu được) mã hoá client-side; không gửi token về máy chủ không cần thiết.

## 4. Khuyến nghị cho extension

**Ưu tiên làm trước (ROI cao, rủi ro thấp, 100% official API):**

1. **Kiểm kê đa-BM dashboard** (read-only): danh sách people, pending users, system users, owned/client assets, agencies, verification_status, ad-account status + spending (fields ở §3.2). Đây là "tác vụ phải click tới kiệt xương" trong Business Info/Settings.
2. **Quản trị người dùng hàng loạt**: invite/remove/đổi role từ CSV (`POST/DELETE business_users`) + offboarding wizard (liệt kê assets người đó đang giữ → gỡ theo nghiệp vụ → remove). Kèm "2FA report" (`two_fac_status`).
3. **Gán/gỡ assets cho people partners hàng loạt** bằng `assigned_users` + Batch API: chọn N người × M asset × task-set, dry-run hiển thị trước những gì sẽ đổi; log kết quả từng call.
4. **System user helper**: tạo system user + gán assets + generate token ngay trong extension (bỏ qua 5–7 màn hình UI), có copy-to-clipboard + cảnh báo bảo mật.
5. **Account health monitor**: quét `account_status`, `disable_reason`, `spend_cap vs amount_spent`, `balance`, funding source hết hạn; cảnh báo trong popup khi có account bị hạn mức/UNSETTLED/RISK_REVIEW.

**Làm sau / cẩn trọng:** 6. Request/claim assets từ BM khác (API gửi yêu cầu + hướng dẫn người dùng nhờ phía kia duyệt) — "hybrid" flow. 7. Agency link/unlink (`/agencies`) cho flow agency-client. 8. Automation UI phần verification/invite-accept/payment: **chỉ nên hỗ trợ điền form**, không nên tự động submit; tài liệu hoá nguy cơ checkpoint cho người dùng.

**Cách tiếp cận an toàn & bền:**

- Pin `v26.0`, đặt cấu hình version ở một chỗ, job nhắc bump mỗi ~6 tháng; thay đổi BM API có thể làm mất fields (ví dụ Business Role Request đã bị thu hẹp qua các version).
- Luôn implement **dry-run + diff hiển thị** cho các write hàng loạt; lưu audit log nội bộ (CSV export) song song với Setting Logs của Meta.
- App Review: xin `business_management` + `ads_management` (Advanced Access) — mô tả use case rõ "BM administration for agencies" và screencast, nếu không chỉ được Standard Access (chỉ chạy cho BM của chính mình).
- Kế hoạch D: khi endpoint bị deprecate, fallback đọc bằng UI link hướng dẫn (deep-link `business.facebook.com/settings/...`), đừng cố cào DOM.
