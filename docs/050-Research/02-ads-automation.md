## 1. Tổng quan

Ads Manager quản trị 3 tầng đối tượng: **Campaign → Ad Set → Ad** (kèm **Ad Creative** map vào Ad). Marketing API của Meta phủ gần như toàn bộ tác vụ CRUD ở 3 tầng này, cộng thêm một **Ad Rules Engine** chạy phía server Meta (bản chất giống Automated Rules trong UI nhưng có thêm chế độ **realtime trigger chỉ qua API**), một bộ **Ads Webhooks** mới (push event thay vì polling), và endpoint **`/copies`** chuyên cho duplicate.

Bối cảnh quan trọng 2025–2026 ảnh hưởng trực tiếp đến thiết kế extension:

1. **Cuộc "tái cơ cấu Advantage+" (thay đổi lớn nhất gần đây):** từ **v24.0 (8/10/2025)** Meta khai tử dần **Advantage+ Shopping Campaigns (ASC)** và **Advantage+ App Campaigns (AAC)** kiểu cũ (`smart_promotion_type=AUTOMATED_SHOPPING_ADS`): v24 chặn tạo/duplicate/sửa trên v24+; **v25.0 (18/2/2026) chặn tạo ASC/AAC trên MỌI version** và đóng băng edit campaign chưa migrate; **v26.0 (29/7/2026)** khóa toàn bộ legacy ASC/AAC (không edit được, ASC dùng `existing_customer_budget_percentage` bị PAUSED). Thay thế là **"Advantage+ campaign experience"** hợp nhất: tạo campaign Sales/App/Leads thường rồi bật 3 lever automation — **Advantage+ audience + Advantage+ campaign budget (trước đây CBO) + Advantage+ placements** — campaign sẽ có `advantage_state=ADVANTAGE_PLUS_SALES/APP/LEADS`. Extension bắt buộc phải theo flow mới này; không được tạo ASC kiểu cũ nữa.
2. **Đổi tên access tier (5/4/2026, out-of-cycle):** "Ads Management Standard Access" → **Marketing API Access Tier**; Standard Access → **Limited Access** (mặc định, dev only), Advanced Access → **Full Access** (production). Ngưỡng auto-approve Full **giảm từ 1,500 → 500 Marketing API calls trong 15 ngày**, bỏ yêu cầu screen recording khi xin upgrade, cửa sổ tính error rate mới: 500 request gần nhất (<15%). → Dễ xin Full access hơn trước.
3. **Rate limit được siết và văn bản hóa rõ (docs cập nhật 8/2026):** thêm giới hạn **100 QPS mutation** (create/edit campaign/adset/ad) theo cặp app+ad account, giới hạn **1 edit/object/30s**, và — rất quan trọng cho tính năng auto-budget — **đổi budget ad set tối đa 4 lần/giờ** (vượt ngưỡng sẽ bị block 1 giờ).
4. **Ads Webhooks (tài liệu mới, docs cập nhật 2026):** Meta đẩy mạnh webhook `ad_account` với 6 field — `effective_status` (đổi trạng thái delivery: bị từ chối, blocked, active trở lại), `with_issues_ad_objects`, `in_process_ad_objects`, `ad_recommendations`, `creative_fatigue`, và `subscriptions` (event create/update + metric vượt ngưỡng tự đặt). → Đây là đường "chính đạo" để theo dõi review status/khóa ad thay vì polling.
5. Meta đang **dồn automation vào AI black-box (Advantage+, Opportunity Score, Andromeda)**: extension không nên cố thay AI mà nên tập trung vào **tác vụ vận hành hàng loạt (bulk ops), guardrail, naming, lịch chạy, và observability** — phần Meta không làm hoặc làm yếu.

### 3.2. Permissions & access tiers

**Permissions (scope):**

- `ads_management` — create/edit/delete ads; bắt buộc cho mọi tác vụ write (kể cả Ad Rules engine).
- `ads_read` — đọc objects + insights.
- `business_management` — khi cần BM assets (pages, catalogs, system users…).

**Hai lớp access phải phân biệt (dễ nhầm):**

1. **Access level theo permission** (platform-wide): _Standard access_ — đủ để quản lý **ad account của chính những người có role trong app** (admin/dev/tester) và những account họ quảng cáo; _Advanced access_ — cần khi app quản lý **ad account của người khác** (App Review).
2. **Marketing API Access Tier** (tên mới, 4/2026; trước đây "Ads Management Standard Access"): **Limited Access** (mặc định khi add product Marketing API — dev only, rate limit rất gắt, BM API hạn chế, 1 system user + 1 admin system user) vs **Full Access** (production: rate limit thoáng, full BM/Catalog API, 10 system users + 1 admin). Upgrade qua App Review; ngưỡng auto-đủ điều kiện: **≥500 Marketing API calls/15 ngày** + error rate <15% (500 request gần nhất).

→ Kịch bản cho extension: cá nhân/agency quản lý account mình sở hữu → **Limited tier + Standard access** đã chạy được end-to-end (có `ads_management`); khi làm cho bên thứ ba → cần Advanced access cho `ads_management`/`ads_read` + Full tier.

### 3.3. Auth trong browser extension

- **User access token** qua Facebook Login OAuth: dialog `https://www.facebook.com/v26.0/dialog/oauth?client_id=<APP_ID>&redirect_uri=<REDIRECT>&scope=ads_read,ads_management&response_type=token|code`. Trong extension dùng `chrome.identity.launchWebAuthFlow`, redirect `https://<extension-id>.chromiumapp.org/` (https, phải whitelist trong app settings "Valid OAuth Redirect URIs").
- Đổi short-lived → **long-lived token (~60 ngày)**: `GET /oauth/access_token?grant_type=fb_exchange_token&…` (cần app secret → nên làm qua backend nhỏ, tránh nhúng secret vào extension).
- Token user **không vô hạn**: hết hạn 60 ngày/mất khi user đổi mật khẩu/gỡ quyền → cần UX renew + lưu mã hóa trong `chrome.storage` (không log, không gửi về nơi khác).
- Server-side (nếu team có backend): **System User token** của BM (không hết hạn, cần Business Verification + Full tier) — mô hình bền cho tính năng giám sát/điều hành 24/7.
- Gọi Graph từ extension: `https://graph.facebook.com/v26.0/...` — cho phép CORS; secret không cần thiết cho read/write bằng user token.

### 3.5. Ad Rules API vs Automated Rules native (so sánh)

| Tiêu chí            | Automated Rules (UI Ads Manager)                                                                         | Ad Rules API                                                                                                                                                                                                                                                                                                                                 |
| ------------------- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Engine              | Chung một rules engine ("ad rules library" ở account level)                                              | Chung engine — rule API tạo vẫn chạy phía Meta 24/7                                                                                                                                                                                                                                                                                          |
| Cách tạo            | UI: `facebook.com/ads/manager/rules/management`                                                          | `POST /act_<ID>/adrules_library`                                                                                                                                                                                                                                                                                                             |
| Loại evaluation     | Chỉ **schedule-based** (check chu kỳ ~30 phút / daily / custom)                                          | `SCHEDULE` + **`TRIGGER` realtime** (`METADATA_CREATION/UPDATE`, `STATS_CHANGE/MILESTONE` — trigger rules **chỉ qua API, không có trong UI**; latency metadata ~vài giây, insights p99 ~7.5 phút)                                                                                                                                            |
| Actions             | Bật, tắt, chỉ thông báo, tăng/giảm daily/lifetime budget, scale budget theo target, tăng/giảm manual bid | `PAUSE, UNPAUSE, NOTIFICATION` (schedule+trigger), `CHANGE_BUDGET, CHANGE_CAMPAIGN_BUDGET, CHANGE_BID, ROTATE, REBALANCE_BUDGET` (schedule), `PING_ENDPOINT` (trigger → webhook); thêm các action nội bộ Meta: `AUDIENCE_CONSOLIDATION(…)`, `AD_RECOMMENDATION_APPLY` (khớp các template UI "Reduce audience fragmentation/auction overlap") |

### 3.6. Advantage+ automation qua API (tháng 10/2026)

- Tạo Advantage+ sales/app/leads: campaign thường + (Advantage+ audience ở ≥1 ad set **hoặc** không set targeting gì trừ `geo_locations` **hoặc** targeting có relaxation) + budget ở campaign level + **không set placement targeting** (default = Advantage+ placements). Objective map: `OUTCOME_SALES`, `OUTCOME_LEADS`, `APP_INSTALLS`.
- Đọc trạng thái: `GET /<CAMPAIGN_ID>?fields=advantage_state_info` → `advantage_state` + 3 sub-flag (`advantage_budget_state`, `advantage_audience_state`, `advantage_placement_state`), tất cả **read-only** — muốn bật/tắt Advantage+ phải đổi lever tương ứng (vd: tắt = set ad set level budget hoặc thêm placement/targeting chặt).
- `smart_promotion_type` hiện `GUIDED_CREATION` cho campaign mới; không được POST ngược về `AUTOMATED_SHOPPING_ADS`.
- Migrate legacy (còn hiệu lực tới trước v26, nay gần như hết thời): `POST /<CAMPAIGN_ID>(/copies)?migrate_to_advantage_plus=true`; exceptions: >50 ads trong ASC ad set (không migrate được nổi), `existing_customer_budget_percentage` (chỉ migrate được trong UI bằng Duplicate Campaign); campaign migrate/copy đều **rơi lại learning phase**.
- Lưu ý v26: HEC-F phải set rõ `targeting_automation.advantage_audience=0|1`; `existing_customer_budget_percentage` bị loại khỏi campaign mới (workaround 2 ad set §2.1-29).

### 3.7. Theo dõi review/khóa (observability)

- Trên Ad: `effective_status` (đầy đủ: `ACTIVE, PAUSED, DELETED, PENDING_REVIEW, DISAPPROVED, PREAPPROVED, PENDING_BILLING_INFO, CAMPAIGN_PAUSED, ARCHIVED, ADSET_PAUSED, IN_PROCESS, WITH_ISSUES`), `issues_info` (danh sách lỗi), `ad_review_feedback`, `recommendations` (AdRecommendation — level + gợi ý hành động; có thể bật khi tạo/sửa bằng `execution_options=include_recommendations`).

- **Ads Webhooks (docs mới 2026)** trên object `ad_account`: `effective_status`, `with_issues_ad_objects`, `in_process_ad_objects`, `ad_recommendations`, `creative_fatigue`, `subscriptions`. Envelope chuẩn `{object:"ad_account", entry:[{id, time, changes:[{field,value}]}]}` — nhận xong vẫn phải poll API để lấy chi tiết.
- Extension thuần client: polling `GET /act_<ID>/ads?fields=name,effective_status,issues_info,recommendations&filtering=[{"field":"effective_status","operator":"IN","value":["DISAPPROVED","WITH_ISSUES","PENDING_REVIEW"]}]` theo `chrome.alarms` là thực dụng nhất; webhook chỉ dùng khi có backend relay.

### 3.8. Lưu ý triển khai cho browser extension (MV3)

1. **Đừng build "scheduler local" cho tác vụ quan trọng 24/7** — MV3 service worker bị suspend; `chrome.alarms` tối thiểu 30s (và chỉ đảm bảo khi browser mở). Tác vụ theo lịch/điều kiện nên **đẩy lên Meta Ad Rules engine**; extension chỉ là rule builder + monitor.
2. **Idempotency & rollback**: ghi operation log (before/after snapshot) cho bulk write; hỗ trợ undo (pause/archive thay delete); dry-run `validate_only` trước bulk import.
3. **Khung chịu lỗi rate limit**: đọc header `X-Business-Use-Case-Usage`, xử lý subcode riêng (`5044001` → giãn QPS; `4841018` → retry sau ≥30s; `1487632` → khóa đổi budget ad set đó 1h trong UI extension; `1487742`/2446079 → exponential backoff).
4. **Naming convention engine ở client** (template `{objective}_{market}_{date}_{seq}` + validator + preview diff trước khi POST rename hàng loạt).
5. **Compliance**: không tự động click/điền trong UI Ads Manager (vi phạm Platform Terms, dễ dính checkpoint tài khoản); mọi hành động qua API; các tác vụ UI-only (appeal review, billing) dùng deep link hướng dẫn.
6. **Bảo mật token**: không nhúng app secret; long-lived token lưu cục bộ, không gửi third-party; logout flow revoke `DELETE /me/permissions`.
7. **Version pinning**: gọi `/v26.0/`, theo dõi Marketing API changelog (auto-generated 2 tuần/lần) và bảng "Available versions" để nâng cấp định kỳ; chú ý các deprecate đã liệt kê (placements, poll, messenger lead forms, `metadata=1`, legacy protocol params bị gỡ từ 27/10/2026: `pretty`, `debug`, `date_format`, `GET /?ids=`, ETag).

## 4. Khuyến nghị cho extension

**Ưu tiên làm trước (MVP an toàn, giá trị cao):**

1. **Read/mirror + Bulk actions**: danh sách 3 tầng theo filter `effective_status`; chọn nhiều → pause/unpause/archive/rename/đổi budget–schedule–bid qua API + batch + confirm dialog + undo log. (Tác vụ 5, 9–16 — API thuần, rủi ro thấp, giá trị ngay.)
2. **Naming convention & bulk rename**: template builder + pre-flight audit (báo tên lệch chuẩn trên toàn account) → rename hàng loạt. Meta không có tính năng này trong UI → differentiator rõ.
3. **Rule builder nâng cao trên Ad Rules API**: UI đơn giản hóa `evaluation_spec/execution_spec/schedule_spec`; bán điểm khác native: trigger realtime (PAUSE khi `effective_status` đổi), `action_frequency`/cooldown, `adrules_history` viewer, templates (kill-CPA-cao, scale-ROAS-tốt ≤20%/lần, dayparting tắt khuya). Extension **không tự chạy rule loop local** mà tạo rule phía Meta.
4. **Review/lock watcher**: polling định kỳ `effective_status` + account `account_status/disable_reason`, bảng "ads bị từ chối / đang review rất lâu / account rủi ro" + deep link tới Ads Manager để appeal (không auto appeal). Nếu sau này có backend: chuyển sang Ads Webhooks.

**Làm sau (cần cẩn trọng hoặc backend):** 5. **Bulk launcher từ Excel/Sheets**: parse local → dry-run `validate_only (+synchronous_ad_review)` → batch create (≤10 ads/batch, async) với dependency chaining; error report theo dòng file. Đây là thay thế hợp lệ cho "Import ads in bulk" UI. 6. **Duplicate studio**: cross-campaign/ad-set copy qua `/copies` + `rename_options`, thêm lớp "copy sang account khác = export spec → create mới" (workaround tự build, vì API không hỗ trợ cross-account). 7. **Advantage+ panel**: đọc `advantage_state_info` hàng loạt, cảnh báo campaign lệch lever (vd: ai đó thêm placement targeting làm `DISABLED`), hỗ trợ bật/tắt lever từ xa. **Không** implement flow ASC/AAC cũ (đã chết ở v25/v26). 8. **Auto-budget theo điều kiện nâng cao** (vd: % theo performance thực, floor/cap riêng): nếu vượt khả năng `CHANGE_BUDGET` của rules engine thì mới làm executor riêng (server/system user token) có cooldown cứng tuân thủ 4 lần/giờ/ad set.

**Cách tiếp cận an toàn/bền:** Official API cho mọi thứ có thể; hybrid cho UI-only bằng deep link (không cào/auto-click UI); Meta-side rules thay local cron; backoff theo subcode + tôn trọng trần budget/spend_cap; token user 60 ngày cho bản personal, system-user backend cho bản team/agency (Full tier); audit log + dry-run là mặc định.
