# Nghiên cứu #12 — Các tính năng tự động NATIVE của Meta (baseline tránh làm thừa)

> Phạm vi: inventory các tính năng tự động hóa mà Meta đã cung cấp sẵn trong **Meta Business Portfolio (trước đây là Business Manager)**, **Meta Business Suite** và **Ads Manager**, tính đến tháng 10/2026 — làm gì được, hạn chế gì khiến người dùng vẫn phải làm thủ công, và khoảng trống (gap) mà extension nên lấp.
>
> **Lưu ý xác thực:** trong phiên nghiên cứu này, `facebook.com/business/help/*` và `developers.facebook.com/*` bị chặn bot (HTTP 400). Các số liệu quan trọng đã được cross-check qua ≥2 nguồn bên thứ ba cập nhật 2025–2026 (Birch/Revealbot — đối tác chính thức của Meta, NapoleonCat, Buffer, Social Media Today, TechCrunch) và qua **probe trực tiếp Graph API**. Những điểm lấy từ tài liệu chính thức Meta nhưng không mở được trong phiên này được đánh dấu _(tài liệu Meta — cần kiểm tra lại trực tiếp khi triển khai)_.

---

## 1. Tổng quan

Meta (Facebook) hiện đã tích hợp khá nhiều “automation” native rải rác trên 3 lớp sản phẩm:

1. **Ads Manager (adsmanager.facebook.com)** — nơi tập trung automation phía quảng cáo: **Automated Rules**, **Advantage+ suite** (sales/app campaigns, audience, creative, placements, campaign budget), **Ads Reporting** (scheduled email reports), **bulk edit & import/export**, **Experiments (A/B test)**.
2. **Meta Business Suite (business.facebook.com)** — trung tâm vận hành nội dung & khách hàng: **Planner** (lên lịch bài đăng FB/IG), **Inbox + Automations** (instant reply, away messages, FAQ, auto-response theo keyword), **Leads Center**, **Content/Appointments**, **notification settings**.
3. **Meta Business Portfolio (đổi tên từ Business Manager năm 2024)** — quản trị tài sản & con người: partner/agency access, system users, quyền theo task, xác minh doanh nghiệp.

Bức tranh chung năm 2025–2026:

- **Meta đẩy mạnh “full automation” bằng AI** theo hướng Advantage+: sản phẩm cũ “Automated Ads” bị khai tử trong 2025–2026 để dồn về Advantage+ (nguồn: Social Media Today, 2025). Tầm nhìn công khai của Meta là “một nút bấm”: doanh nghiệp chỉ nêu mục tiêu, AI lo phần còn lại (phát biểu của Zuckerberg, trích trong SMT 2025).
- Tuy nhiên, các công cụ tự động native **thiên về tối ưu hiệu suất quảng cáo (black-box)**, còn các tác vụ vận hành hằng ngày (giám sát, báo cáo, đăng bài hàng loạt, moderation, onboarding agency, cảnh báo chủ động) vẫn **rất thủ công hoặc giới hạn chặt** — đây chính là khoảng trống cho extension.
- Ngày 11/10/2026, Meta **gỡ bỏ “access verification”** cho developer truy cập business data của khách hàng — chỉ còn Business Verification + App Review (nguồn: SMT, 11/10/2026). Đây là tín hiệu Meta nới điều kiện cho bên thứ ba, thuận lợi cho việc build extension dựa trên Official API.
- Probe trực tiếp `https://graph.facebook.com/v{XX}.0/me` (12/10/2026): **v21.0 → v26.0 đều còn sống; v27.0 chưa tồn tại** → Graph API mới nhất hiện tại là **v26.0**; v21.0 sắp hết vòng đời (chu kỳ ~2 năm).

## 3. Chi tiết kỹ thuật

### 3.1. Trạng thái nền tảng (đã probe ngày 12/10/2026)

- **Graph API mới nhất: v26.0.** Probe `GET https://graph.facebook.com/v{XX}.0/me` trả lỗi OAuthException 2500 (“an active access token must be used…”) cho v21.0–v26.0 (= version tồn tại), và “Unknown path components” cho v27.0 (= chưa phát hành). → Build nên pin tối thiểu **v23.0+** để kéo dài thời gian sống; chu kỳ deprecate ~2 năm/version.
- **Oct 2026: Meta gỡ “access verification”** cho app truy cập business data của khách hàng; vẫn yêu cầu **Business Verification** cho business sở hữu app + **App Review** cho permission nâng cao (nguồn: SMT, 11/10/2026). → Thuận lợi hơn cho extension agency-facing nhưng App Review vẫn là nút thắt.

### 3.2. Endpoint & permission chính (Marketing API / Graph API)

_(Đường dẫn tài liệu chính thức liệt kê ở mục 5; nội dung dưới cross-check qua SDK/blog đối tác — khi triển khai phải đọc lại tài liệu Meta trực tiếp vì dev docs không truy cập được trong phiên này.)_

- **Automated Rules — Ad Rules Engine:**
  - `GET/POST /{ad_account_id}/adrules_library` — list/tạo rule; `GET/POST/DELETE /{rule_id}`.
  - Cấu trúc rule: `evaluation_spec` (filters: entity_type, time_preset, evaluation_type=TRIGGER/SCHEDULE), `execution_spec` (execution_type: PAUSE/UNPAUSE/CHANGE_BUDGET/CHANGE_BID/NOTIFICATION/ROTATE/REBALANCE_BUDGET…), `schedule_spec`.
  - Permission: `ads_management` (và `ads_read` để đọc). **Giới hạn 250 rule/ad account** (nguồn: Birch; tài liệu Meta — kiểm tra lại).
  - Lịch check: `schedule_type` SEMI_HOURLY/…(“continuous” native ≈ 30 phút, daily, custom).
- **Campaign/Ad set/Ad management:** `/act_{id}/campaigns`, `/{campaign_id}/adsets`, `/{ad_id}` — CRUD + status; `POST` batch qua `/act_{id}` (tối đa 50 request/batch, có `batch API` tổng quát). Permission `ads_management`.
- **Insights API:** `GET /{id}/insights` với `level`, `breakdowns`, `time_range`, `action_breakdowns`; report lớn chạy **async** (`/{report_run_id}` polling). Permission `ads_read`.
- **Page publishing/scheduling:** `POST /{page-id}/feed` (`published=false` + `scheduled_publish_time` ≤ 75 ngày — kiểm tra lại), `/{page-id}/photos|videos`, scheduled reel flow 2 bước. Permission `pages_manage_posts` (+ `pages_read_engagement`, Page access token từ `/me/accounts`).
- **Comments moderation:** `GET /{post-id}/comments`, `POST /{comment-id}/replies`, `POST /{comment-id}` `{is_hidden: true}`; ad comments đọc qua ad → effective_object_story_id. Permission `pages_manage_engagement`.
- **Messenger/DM:** Messenger Platform (`/{page-id}/messages`), window 24h; `pages_messaging` (App Review). FAQ/away message native **không có public API đầy đủ** → nếu muốn replicate phải dùng webhook + tự build logic (đây là hybrid: extension polling webhook không khả thi thuần client → cần server đồng hành hoặc chấp nhận polling).
- **Leads:** `GET /{form-id}/leads`, webhook `leadgen`. Permission `leads_retrieval` (+ `pages_manage_ads`).
- **Business/Portfolio:** `/{business_id}`, `/business_users`, `/pending_users`, `/owned_ad_accounts`, `/client_ad_accounts`, system users. Permission `business_management` (App Review nặng).
- **Ads Reporting native (UI) không có public API “schedule email”** — muốn vượt giới hạn phải tự build report (Insights) + tự gửi.

### 3.3. Cơ chế auth cho browser extension

- OAuth: của extension nên đi qua **backend riêng** (an toàn nhất): user login Facebook → code → server đổi lấy **long-lived user token (~60 ngày)** → server cấp session cho extension. Nếu thuần client: `chrome.identity.launchWebAuthFlow` + `https://www.facebook.com/v26.0/dialog/oauth`, đổi token bằng `fb_exchange_token` (cần app secret → **không được nhúng secret trong extension** → bắt buộc backend nếu muốn long-lived).
- App Meta: tạo loại **Business**, thêm sản phẩm Marketing API (+ Pages, Messenger nếu cần), chạy **App Review** cho `ads_management`, `ads_read`, `business_management`, `pages_manage_posts`, `pages_manage_engagement`, `pages_messaging`, `leads_retrieval`.
- System user token (cho agency server-side): từ Business Portfolio → vô thời hạn nếu `never expiring` (vẫn chịu revoke).
- Nhiều ad account: user grant 1 lần → liệt kê `/me/adaccounts` → store mapping account→token scope.

### 3.4. Rate limits (cần thiết kế backoff)

- Headers trả về: `x-app-usage`, `x-ad-account-usage`, `x-business-use-case-usage`, `x-fb-ads-insights-throttle` → thiết kế **adaptive throttling** đọc `call_count`/`total_cputime`/`estimated_time_to_regain_access`.
- Lỗi throttle điển hình: code 4 (app-level), 17 (user-level), 613 (calls too many), 80004 (ads insights throttle). Insights bị throttle ~ score cao khi breakdown nặng → tối ưu bằng async reports + cache.
- Batch tối đa **50 calls/request**; nên gom mutation dạng batch để giảm quota.
- **Lưu ý triển khai cho extension:** MV3 service worker ngủ sau ~30s → dùng `chrome.alarms` (chu kỳ ≥30s thực tế ~1 phút+) cho polling; insight polling lớn để server làm thay nếu cần tần suất cao; token & rule config lưu `chrome.storage.local` (cân nhắc mã hoá) / sync server.

## 4. Khuyến nghị cho extension

**Định vị sản phẩm:** đừng tái tạo Advantage+ hay thuật toán của Meta — hãy là **“lớp kiểm soát + vận hành”** phía trên các công cụ native: giám sát, cảnh báo, hàng loạt, chuẩn hoá quy trình agency. Đây đúng là whitespace đã được kiểm chứng bởi thị trường (Birch/Revealbot, Madgicx, NapoleonCat sống khoẻ nhờ những gap này).

Ưu tiên (từ cao xuống):

1. **Alert & monitoring đa kênh (gap #11, #1)** — độ khả thi cao, rủi ro thấp, giá trị tức thì: anomaly alert spend/CPA/ROAS, gửi Slack/Telegram/email, extension dùng `chrome.alarms`. Native hoàn toàn thiếu kênh ngoài Meta.
2. **Rule nâng cao + template + execution log (gap #1)** — build trên Ad Rules Engine cho phần tương thích, phần action mở rộng (duplicate/rename/đổi bid strategy/spending limit, OR-nesting, custom timeframe, ranking %) chạy bằng scheduler riêng gọi Marketing API. Backup/sync rule giữa ad accounts cho agency.
3. **Bulk ops có dry-run (gap #9)** — bulk launcher ma trận creative×audience, naming/UTM macro, rename hàng loạt, validate trước push, rollback. Toàn bộ làm được bằng API chính thức → an toàn & bền.
4. **Scheduler đa Page + bulk CSV + recurring (gap #7)** — Graph API `/feed` hỗ trợ sẵn scheduled post → chỉ cần UX tốt hơn native (native = 1 Page/lần + không bulk). Rất phù hợp extension (form post trực tiếp, không webhook).
5. **Report cross-account gửi bất kỳ ai (gap #12)** — Insights API + template agency, vượt hạn chế “chỉ người có quyền ad account”.
6. **Inbox/comment automation nâng cao (gap #8)** — chỉ khi đã có App Review `pages_messaging` + `pages_manage_engagement`; đây là phạm vi nặng (24h window, ad comments edge cases) → để phase 2, làm trước **ad comment moderation rule + auto-hide spam** (API comments sẵn có).
7. **Agency onboarding/audit (gap #10)** — checklist + audit quyền qua BM API; các bước Meta không mở API thì extension hỗ trợ ngay trong UI (content script hướng dẫn/prefill) — hybrid có kiểm soát.

**Cách tiếp cận an toàn/bền:**

- **Official API first; browser automation chỉ là fallback read-only** cho mảng Meta không mở (Account Quality, một số màn Inbox). Tự động hoá UI `business.facebook.com` bằng click-through là rủi ro cao (UI thay đổi liên tục + rủi ro ToS) — tránh thiết kế cốt lõi dựa vào nó.
- Kiến trúc: **extension = UI + cache + scheduler nhẹ; backend companion = token exchange, webhook (leadgen/messages), cron nặng**. Extension thuần client vẫn làm được 1→5 với `chrome.alarms` + long-lived token + yêu cầu user re-auth định kỳ.
- Thiết kế ngay từ đầu: pin API version v23+, adaptor theo version; đọc rate-limit headers; mọi mutation có dry-run + log + undo; tách biệt dữ liệu từng ad account.
- Tránh xung đột với native: nếu user bật cả Automated Rules native và rule của extension, phải có màn “conflict detector” (cùng action trên cùng object) — đây cũng là feature bán được.
- Luồng giá trị nhanh nhất để demo: **Insight polling → anomaly → Slack alert** và **bulk rename/UTM** (2 flow hoàn toàn trong quyền `ads_read`/`ads_management`, dễ xin App Review).
