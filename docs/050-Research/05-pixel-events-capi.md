# Nghiên cứu 05: Tự động hóa Pixel/Dataset, Events & Conversions API (CAPI)

> Trạng thái tại: tháng 10/2026. Phiên bản Graph API mới nhất: **v26.0** (ra mắt 29/07/2026), Marketing API v26.0 tương ứng; Business SDK chính thức: v26.0.2 (auto-generated từ Graph API — dùng làm nguồn ground-truth cho endpoints vì developers.facebook.com chặn crawl trực tiếp).

---

## 1. Tổng quan

- **Pixel đổi tên thành Dataset**: Trong Events Manager (EM) Meta đã đổi "Meta Pixel" thành **"Dataset"** — dataset là nơi gom event từ nhiều nguồn (Pixel browser, CAPI server, app events, offline events, messaging). Tuy nhiên **đối tượng API vẫn tên `ads_pixel`** và pixel ID = dataset ID (cùng một ID).
- **Ranh giới API vs UI rất rõ ràng**:
  - **Qua Official API được hoàn toàn**: tạo/đổi tên dataset, liệt kê/audit, chia sẻ cho ad account & BM khác, gán user, gửi server events (CAPI) + test events, đọc stats event (browser vs server, match keys, kết quả xử lý), tạo custom conversions.
  - **Buộc phải thao tác UI (Events Manager / BM Settings) → cần browser automation**: xác minh domain (verify), cấu hình Aggregated Event Measurement (xếp hạng 8 events — đang được Meta đơn giản hóa dần), xem kết quả Test Events, xem Event Match Quality (EMQ 0–10), đọc Diagnostics chi tiết, deploy CAPI Gateway (self-serve trong EM + AWS/Terraform).
- Lý do người dùng BM cần tự động hóa mảng này: agency/via nuôi nhiều BM phải tạo pixel hàng loạt, chia sẻ pixel vào nhiều ad account, giám sát event hỏng (pixel chết, dedup sai, PII violation) và đảm bảo CAPI hoạt động khi browser-side signal suy giảm (ITP, ad blocker, ATT).
- **v26.0 không có breaking change cho khu vực pixel/dataset/CAPI** — blog giới thiệu v26 chủ yếu động vào ads/creative; các endpoint trong báo cáo này ổn định nhiều phiên bản và an toàn để build.

## 3. Chi tiết kỹ thuật

### 3.1 Endpoint chính (Graph API v26.0, ground-truth từ Business SDK v26.0.2)

Dataset/Pixel quản trị:

```
POST   /act_{ad-account-id}/adspixels            {name}                       # tạo dưới ad account
POST   /{business-id}/adspixels                  {name, is_crm}               # tạo dưới BM (dataset)
GET    /{business-id}/owned_pixels | /client_pixels | /ads_dataset
POST   /{pixel-id}   {name, enable_automatic_matching, automatic_matching_fields,
                      first_party_cookie_status, data_use_setting,
                      server_events_business_ids(_add/_remove)}
GET    /{pixel-id}/shared_accounts | POST (account_id,business) | DELETE
GET    /{pixel-id}/adaccounts
GET    /{pixel-id}/shared_agencies | POST /{pixel-id}/agencies (business, permitted_tasks) | DELETE
POST|GET /{pixel-id}/assigned_users (user, tasks)
```

Events:

```
POST   /{pixel-id}/events                       # Conversions API (server events)
       params: data (list event obj), test_event_code, partner_agent,
               namespace_id, upload_id, upload_tag, upload_source, trace
GET    /{pixel-id}/stats                        # AdsPixelStatsResult
       params: event, event_source, agent, start_time, end_time, aggregation
       aggregation ∈ {event, event_source, match_keys, event_processing_results,
                      event_detection_method, had_pii, host, url, pixel_fire, ...}
GET    /{pixel-id}/offline_event_uploads
GET    /{pixel-id}/da_checks                    # dynamic ads checks
GET    /{pixel-id}/openbridge_configurations    # CAPI Gateway / signal gateway configs
POST   /{business-id}/openbridge_configurations # quản config gateway (partner-level)
POST   /act_{ad-account-id}/customconversions   # custom conversions
```

Cấu trúc event CAPI (server-side SDK, `facebook_business/adobjects/serverside/`): `event_name, event_time (unix), event_id, event_source_url, action_source (website/app_store_checkout/...), opt_out, user_data {em, ph, fn, ln, db, ge, ct, st, zp, country, external_id, client_ip_address, client_user_agent, fbc, fbp}, custom_data {value, currency, content_ids, content_type, order_id, ...}`. PII phải hash **SHA-256** (normalize trước: lowercase, trim). Response trả về `events_received`, `fbtrace_id`, `messages` (cảnh báo).

### 3.2 Auth & permissions

- **App type Business + Marketing API product**; app phải link vào BM ở Settings → Advanced để thấy asset.
- Quyền cần:
  - `ads_management` — tạo/quản pixel dưới ad account, gửi CAPI, custom conversions.
  - `business_management` — đọc/quản asset BM: owned_pixels, shared_accounts/agencies, assigned users, ads_dataset.
  - `ads_read`, `read_insights` — nếu chỉ đọc.
- **Token**: system user token (không hết hạn) là chuẩn cho automation; long-lived user token 60 ngày nếu tự gia hạn. CAPI chạy tốt với system user token được gán quyền vào pixel.
- Truy cập pixel xuyên BM: pixel chỉ can thiệp được khi token acting-on đúng business (param `business={bm_id}` bắt buộc trên nhiều edge: shared_accounts, agencies, assigned_users, adaccounts).

### 3.3 Rate limits & hiệu năng

- Marketing API dùng **Business Use Case (BUC) rate limit theo ad spend tier**; đọc header `X-Business-Use-Case-Usage` trên mọi response; >80% thì throttle, 100% → error 17 (user request limit) hoặc 4 (app limit). Backoff exponential từ 60s.
- **Graph batching**: tới 50 sub-request/HTTP request — dùng cho tạo pixel hàng loạt & audit nhiều pixel.
- **CAPI**: batch tới **1.000 events mỗi request**; giữ latency tốt — không có quota công khai nhưng theo BUC khi qua marketing stack; nên retry trên `fbtrace_id` để Meta hỗ trợ.
- Versioning: ghim rõ `v26.0` trong mọi URL; version sống ~2 năm; theo dõi changelog.

### 3.4 Dedup & chất lượng dữ liệu (ngoài API, nhưng là logic extension cần tôn trọng)

- Dedup browser↔server: cùng `event_name` + cùng `event_id` (timestamp gần nhau). Pixel: `fbq('track','Purchase',data,{eventID})`; CAPI: field `event_id`.
- Kiểm chứng bằng `stats?aggregation=event_source`: tin cậy hơn là dùng Test Events UI cho từng phiên test.
- EMQ tốt khi có em/ph/external_id + fbc (từ `fbclid`) + fbp + ip/UA. `stats?aggregation=match_keys` cho biết tỉ lệ event mang key nào → extension tính "EMQ proxy score" nội bộ.
- PII violation: `stats?aggregation=had_pii` giúp phát hiện event lộ PII nhạy cảm.

### 3.5 Lưu ý triển khai cho browser extension (MV3, Vite+CRXJS)

- `host_permissions`: `https://graph.facebook.com/*` cho API calls; `https://business.facebook.com/*` + `https://www.facebook.com/*` cho content scripts thao tác EM/BM UI.
- **Không nhúng token vào content script** — token nằm trong `chrome.storage.local` (hạn chế trang nào cũng đọc) hoặc tốt hơn storage riêng của background service worker, truyền qua `chrome.runtime.sendMessage`.
- MV3 service worker ngủ sau ~30s → dùng `chrome.alarms` cho polling health-check (`last_fired_time`/stats) thay vì interval dài.
- OAuth: `chrome.identity.launchWebAuthFlow` (KHÔNG `getAuthToken` — đó là của Google) trỏ sang app Meta; hoặc cho người dùng dán system user token (mô hình internal tool).
- CAPI từ extension: gửi được trực tiếp `POST /{pixel-id}/events` từ background — đây là CAPI "từ máy người dùng", chỉ phù hợp test/diagnostic; CAPI production phải từ server/gateway của khách.
- Browser automation cho EM: UI của EM dùng GraphQL nội bộ thay đổi thường xuyên — nên chọn chiến lược **DOM + accessibility snapshot** (goto URL cố định + đọc/click theo text), tránh reverse-API nội bộ (fragile, có thể vi phạm ToS).
- Anti-pattern cần tránh: headless scraping bằng cookie chính của user với tần suất cao (rủi ro checkpoint/khóa tài khoản). Chỉ tự động hóa UI khi API không hỗ trợ, tần suất thấp, có jitter.

## 4. Khuyến nghị cho extension

**Ưu tiên 1 — API thuần, giá trị cao, rủi ro thấp (làm trước):**

1. **Dataset inventory & health dashboard**: liệt kê toàn bộ pixel nhiều BM (`owned_pixels`, `client_pixels`), hiển thị `last_fired_time`, `is_unavailable`, ad account đang gắn (`shared_accounts`), cảnh báo pixel im lặng >X giờ. Pure API.
2. **Tạo + chia sẻ dataset hàng loạt**: form nhập {BM, ad account list, tên/quy tắc đặt tên} → batch tạo + `shared_accounts` + gán `assigned_users`. Pure API.
3. **Dedup & signal-quality monitor**: `stats?aggregation=event_source|match_keys|had_pii|event_processing_results` per event; báo ĐỎ khi server=0 (CAPI không chảy), browser≈server (khả năng không dedup), PII>0.
4. **CAPI test sender**: gửi event mẫu với `test_event_code` (sinh code), kèm hướng dẫn mở EM Test Events để đối chiếu (hybrid).

**Ưu tiên 2 — chaos ít, dùng nhiều:** 5. Custom conversions tạo hàng loạt; AAM toggle hàng loạt (`enable_automatic_matching` + `automatic_matching_fields`); first-party cookie rollout. 6. Backup/restore cấu hình tracking (snapshot toàn bộ dataset config + sharing của một BM).

**Ưu tiên 3 — UI-dependent, làm sau & cẩn thận (browser automation):** 7. Domain verification: extension hướng dẫn + điền form, sau đó đọc lại trạng thái qua `OwnedDomain` API (nếu có quyền) hoặc bằng DOM trên BM Settings. 8. AEM/web event configuration: chỉ automate nếu account còn màn 8-event; UI thay đổi theo rollout — bắt buộc browser automation có fallback thủ công. 9. Scraper/hỗ trợ đọc EMQ, Diagnostics, Test Events viewer → tổng hợp cảnh báo tập trung. Không reverse-GraphQL nội bộ. 10. CAPI Gateway: extension ở vai trò "guide + giám sát" (`openbridge_configurations` đọc trạng thái, cảnh báo khi `active=false`/publishing DISABLED); bước deploy AWS/Terraform để user tự thực hiện trong EM.

**Nguyên tắc an toàn/bền:** mọi thứ có API → dùng API (ổn định qua v26); UI automation chỉ tọa thành "copilot" điền-sẵn + xác nhận, tránh click-through hoàn toàn để giảm rủi ro tài khoản; mọi hành động tạo/chia sẻ asset đều ghi audit log trong extension.
